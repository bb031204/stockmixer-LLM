# StockMixer + LLM：当前流程、数据问题与后续实施方案

更新日期：2026-11-17。本文是当前文件与产物的检查记录及后续开发方案，不代表后续功能已经实现。

2026-11-17 补充：新增第 5.4 节“市场通道可用性漏斗”和第 7 节“市场通道专项”，重点处理市场信息准确性不足、1903 条可编码新闻中真正进入市场通道的记录过少两个问题。补充内容同样只是检查记录和方案，未修改源码、配置或原始数据。

## 1. 当前结论与修改边界

当前已经建立新闻离线处理、标准行业代码、历史成员匹配、FinBERT 编码及三通道面板，但公司和行业通道覆盖明显不足。现有产物主要能够验证流程，尚不足以支持可信的三通道融合增益结论。

主要问题依次是：公司身份和历史行业成员覆盖不足、新闻与数据集历史区间重合不足、行业识别与过滤质量尚未充分评估、多行业新闻共用文章级表示。应优先补数据与映射，再优化表示，最后开展正式融合实验。

市场通道不依赖历史行业成员表，是当前最容易扩大有效覆盖的通道。它的主要瓶颈在审核环节：514 条新增或变更记录从未送入 Qwen 审核，一直保持 pending；上游 `impact_scope` 的 market 标签精确度低；审核证据大多来自生成摘要，而不是原文。因此市场通道专项（第 7 节）可以与第一步并行，并优先于第二步。

后续保持以下边界：

- 保留当前 StockMixer 行情主干、原有参数、行情数组、标签与评估函数；不通过修改主干来解决新闻稀疏问题。
- 新增修改集中在上游新闻增强、主数据、新闻关联、特征面板、质量检查和新闻融合配置。
- 原始新闻 JSON 只读；所有增强结果另存、带版本，并能追溯到原记录。
- Qwen 和 FinBERT 在训练前离线运行；训练循环只读取预计算特征。
- 公司、行业、市场通道独立保存特征和 mask；缺失通道的预测修正为零。
- E0 与融合实验使用相同的股票池、时间协议、标签、训练切分、选模和评价口径。

本轮仅编写本文，不修改源码、配置、原始数据，不启动采集、模型推理或训练。

## 3. 当前已经实现的真实处理链路

```text
原始新闻 JSON（只读）
        │
        ├─ 新闻内容 + 行业字典候选 → 上游 Qwen
        │                           │
        │                           └─ 标准行业代码、作用域、证据、机制
        │
        └─ 标题 + 摘要 → 冻结 FinBERT → 情绪概率 + 768 维文章向量
                                      │
                  按 source_id 及版本绑定关联结果
                                      │
           ┌──────────────────────────┼────────────────────────┐
           ↓                          ↓                        ↓
     已核验公司身份           标准行业码 + 历史成员表      已审核市场范围
           ↓                          ↓                        ↓
       公司对应股票              当期行业成员股票           目标市场股票
           └──────────────────────────┼────────────────────────┘
                                      ↓
                         按各数据集预测时点对齐与聚合
                                      ↓
                      company / industry / market 特征及 mask
                                      ↓
                     独立 Adapter、Gate 与行情预测残差融合
```

### 3.1 谁负责找行业、找股票

- Qwen：理解新闻、从字典候选选择行业、判断公司级或行业级影响、保留证据及机制。
- 映射程序：按标准行业代码、历史有效时间和股票身份表找到具体个股及数组位置。
- FinBERT：编码新闻文本，输出情绪及语义向量；不负责查行业、不根据公司名称猜股票代码。
- StockMixer 与融合层：学习新闻特征对收益率预测的增量作用，不直接把 Qwen 的影响方向当作收益标签。

FinBERT 不需要用“银行 / Bank”等名称查找行业。当前正式匹配键是 `industry_standard + industry_version + industry_code`，而不是自由文字名称。

### 3.2 行业字段已统一，但原始旧字段仍保留

当前派生结果中的实际行业记录示例：

```json
{
  "industry_key": "SEC-SIC:6022",
  "industry_standard": "SEC-SIC",
  "industry_version": "EDGAR-SIC",
  "industry_code": "6022",
  "industry_name_standard": "STATE COMMERCIAL BANKS"
}
```

- `industry_enrichment.classified_industries`：字典行业提及，包含公司自身所属行业。
- `industry_impacts`：通过当前作用域与证据检查、可供下游建立行业影响关联的记录。
- 原始“涉及行业”和旧 `industries`：保留来源与审计，不直接代替正式行业影响接口。
- 进入 `industry_impacts` 后，仍必须通过历史成员、日期和预测可用时间检查，才可能变成有效面板。

“银行公司发布自身财报”可以有银行行业提及，但不能自动传播给所有银行股。

### 3.3 当前实现与理想流程的差异

1. Qwen 每次看到的不是完整行业字典，而是检索出的候选；当前旧库批处理候选上限为 12。正确行业未被检索出来时，Qwen 无法选到。
2. 新采集流程可以读取提取后的原文；本次旧库补处理主要读取已有标题与摘要，不能称为重新审核了全部原文。旧原文缺失时应明确标记，不能用生成内容补作原文证据。
3. 当前一篇文章只做一次 FinBERT 编码；关联多个行业时复用同一文章表示，没有分别计算行业条件化情绪。
4. 当前行业关联直接落到股票与日期聚合，没有单独保存可查询的“行业×交易日”特征中间层。
5. 当前正式行业标准采用已获授权的 SEC-SIC。字典中的其他参考分类不能在没有经过验证的跨分类映射时混用。

### 5.4 市场通道可用性漏斗（2026-11-17 补充检查）

数据来源：`outputs\artifacts\news\routing_reviews\20261117_162900_<DATASET>_legacy_extended_v2\market_review.jsonl` 及其 `manifest.json`，统计时只读这些文件。NYSE、SP500 的审核由同一份美国市场审核按数据集重新绑定得到，决定与 NASDAQ 相同，差别只在落入各自日期区间的数量。区间按发布年份前缀粗略统计（NASDAQ/NYSE 取 2013～2017 全年，SP500 取 2016-01～2022-05），比行情轴略宽，正式数字应由第一步的审计脚本按交易日轴重算。

| 阶段 | 全部快照 | NASDAQ/NYSE 区间内 | SP500 区间内 |
|---|---:|---:|---:|
| 可编码英文文章 | 1903 | 927 | 1146 |
| 上游 `impact_scope` 含 market（候选） | 748 | — | — |
| 审核决定 include | 124 | 56 | 81 |
| 审核决定 exclude | 1209 | — | — |
| 审核决定 pending | 570 | 261 | — |
| 其中从未审核（`unreviewed_new_source` / `unreviewed_changed_source`） | 514 | 237 | 381 |
| 其中模型低置信或不确定 | 17 | — | — |
| 区间内候选被排除 | — | 191 | — |

结合第 5.2 节，NASDAQ/NYSE 区间内只有 56 条 include，最终形成训练 126 个、验证 68 个、测试 32 个有效预测日期；同一新闻按 `lookback_sessions: 5` 延续多个交易日，因此有效日期数大于文章数。

根据上述数据得出的判断：

1. **数量瓶颈主要来自未审核，而不是审核拒绝。** 区间内 pending 中 237 / 261 条（SP500 区间内 381 条）属于扩展快照新增或文本变更的记录，`legacy_extended` 审核只复用旧决定，没有为它们调用 Qwen。这部分是当前最直接、也不降低证据标准的增量来源。
2. **上游 market 标签的精确度很低。** 748 条候选中只有 124 条通过审核。抽查区间内 40 条被排除的候选，绝大多数是单一公司的 8-K / 10-K / 6-K 申报、财报、并购、信用协议或品牌更新，排除是合理的。上游标签只能作为召回线索，不能作为市场路由依据。
3. **审核证据大多来自生成摘要。** 1903 条中有 1654 条标题为空，审核的 `evidence_quote` 只能取自摘要。至少 82 条摘要带有 “The document …”“likely”“appears to” 等推测性措辞，例如 “The press release is likely related to financial or corporate updates from Apple Inc.”。这类摘要是上游模型对原文的转述，从中逐字摘出的引文不能证明原文有这句话，市场审核实际上在核验模型自己的输出。
4. **准确率尚未测量。** 现有语义抽检 30 条，其中只有 3 条是人工确认。`min_confidence: 0.85` 是模型自评阈值，不能换算成 include 的精确率。
5. **独立事件数小于文章数。** 同一次 FOMC 决议、同一份 CPI 公告可能有多篇转载或评论。当前去重只按 `input_text_hash` 处理完全相同的文本，改写后的同一事件会重复计入。

## 6. 具体问题、原因与后果

| 问题 | 当前原因或证据 | 实验后果 |
|---|---|---|
| 公司通道覆盖集中 | 整个面板仅覆盖 1 / 2 / 1 只股票 | 无法充分学习跨公司的新闻增量，容易局限于个别公司 |
| 行业成员缺连续历史 | 部分 SEC 观察仅当天有效，其他日期保持未核验 | 行业选对仍无法落到个股，SP500 当前行业通道为零 |
| 行业候选召回未知 | 旧批次先检索最多 12 个候选 | Qwen 不能选取未进入候选的正确代码 |
| 提及与影响需要进一步评估 | 930 条含标准行业提及，25 条通过当前行业影响检查 | 可能存在合理排除，也可能存在误拒，不能据此推算识别准确率 |
| 旧文本不完整 | 批处理主要使用已存摘要 | 摘要遗漏的行业和机制不能可靠恢复 |
| 多行业共用表示 | FinBERT 一篇文章只编码一次 | 无法显式区分同一事件对不同行业的相反作用 |
| 最低就绪门槛太低 | `pipeline.minimum_training_cells: 1` | 能运行不等于样本足够，NYSE 5 个行业单元也可通过 |
| 部分审核尚待补齐 | 新增和版本变化记录不会自动继承旧市场审批 | 有文本特征不等于可以发布为市场训练关联 |
| 时间口径容易误读 | 旧新闻在 2026 年重新增强 | 当前属于 retrospective，不能声称特征在原历史年份真实在线可用 |
| 市场新闻大量未审核 | 514 条新增或变更记录保持 `unreviewed_*`，从未调用 Qwen | 市场通道有效日期偏少；这些记录不是被拒绝，而是没有被处理 |
| 上游 market 标签噪声大 | 748 条候选中 124 条 include，被排除的多为单公司申报和财报 | 直接使用上游标签会把公司事件广播给全市场 |
| 市场证据来自生成摘要 | 1654 / 1903 条无标题，至少 82 条摘要带推测性措辞 | 逐字证据校验只能证明引文在摘要里，不能证明在原文里 |
| 市场审核准确率未知 | 30 条抽检中 3 条为人工确认 | 无法判断 include 的精确率，也无法依据数据确定置信阈值 |
| 事件重复计数 | 去重只看完全相同的文本 | 改写转载会夸大独立事件数和训练样本多样性 |

面板拒绝计数、实体关联失败计数可能对应不同阶段和统计单位，不能相加后直接当作失败文章总数。

## 7. 后续实施路线：按依赖顺序推进

### 市场通道专项：提高准确性与有效覆盖（可与第一步并行）

市场通道按日期共享（`market_layout: shared_date`），不需要历史行业成员表，也不需要逐股票身份核验。它是现有数据下最有希望在训练、验证、测试三个切分上都形成可评价覆盖的通道。下列工作只涉及新闻增强、审核、路由和面板，不改动 StockMixer 主干、行情数组、标签或评估函数。

依赖顺序：M1 与 M2 可以立即开始；M3 需要先完成 M2；M4 与 M5 在 M1 之后进行；M6 在 M3、M4、M5 完成后进行。

#### M1：完成未审核记录的市场审核（只补处理，不放宽标准）

问题：514 条记录因为在扩展快照中是新增或文本变更的，被标为 `unreviewed_new_source` / `unreviewed_changed_source`，没有调用 Qwen 审核。

涉及现有文件：`news_fusion\auto_review.py`（`auto_review(..., source_ids=...)` 已支持只审核指定记录）、`news_fusion\legacy_industry.py`（`validate_extended_review`）、`scripts\02_review_news.py`、`configs\llm.yaml` 中的 `review` 段。

具体工作：

1. 从当前 `legacy_extended_v2` 审核中取出 `review_method` 以 `unreviewed_` 开头的 `source_id`，只把这些记录送入现有 `auto_review`；Prompt（`us_market_relevance_v2`）、模型 digest、`min_confidence: 0.85` 均保持不变，以便新旧决定可以比较。
2. 结果写入新版本目录 `outputs\artifacts\news\routing_reviews\<年月日_时分秒>_<DATASET>_market_review_v3\`。已有的 1209 条 exclude、124 条 include 原样保留，并记录来源审核的 manifest SHA256，不重新判定。
3. 按数据集分别报告新增 include / exclude / pending 的数量，以及区间内新增的有效日期数。

预期：这一步能增加的数量有上限。NASDAQ/NYSE 区间内即使 261 条 pending 全部被 include，区间内的 include 也只会从 56 条增加到约 317 条；参照已审核记录约 9%（124 / 1333）的 include 比例，实际增量可能只有数十条。M1 解决的是“可用数据没有被处理”，单靠它不足以让市场通道达到正式实验的样本量，还需要 M3。

验收：514 条均有 include / exclude / pending 决定及审核时间；`known_from` 取真实审核完成时间，不倒填；新增 include 均通过现有 `checked_reviews` 的逐字证据校验。

#### M2：区分原文证据与模型摘要证据

问题：`checked_reviews` 只要求 `evidence_quote` 出现在 `title + summary` 中。1654 条记录标题为空，摘要是上游模型生成的转述，引文通过校验并不能说明原文支持该市场判断。

具体工作：

1. 在下游适配快照中为每篇文章增加 `text_origin` 字段，取值为 `source_title`、`source_excerpt`、`model_summary`、`unknown`。该字段只能来自上游采集记录中已有的来源信息，无法确定时记 `unknown`，不根据文本风格推断。
2. 市场路由增加 `evidence_basis`：引文出现在原文或原文摘录中时记 `source_text`，只出现在生成摘要中时记 `generated_summary`。
3. 正式实验默认只使用 `evidence_basis: source_text` 的市场路由；`generated_summary` 路由作为单独的消融版本，不与前者混合后报告为同一结果。
4. 能从上游恢复原文的记录另存为新证据版本，然后重新审核（与第 3 步的补采工作衔接）；恢复失败的记录保留缺失状态。
5. 对摘要中出现 “likely”“appears to”“The document …” 等措辞的记录进行标记统计，作为摘要质量的报告项，不作为自动排除规则。

涉及现有文件：`news_fusion\source_adapter.py`、`snapshot.py`、`routing.py`（`binding`、`checked_reviews`），以及上游 `U\offline_enrichment\`。改动 `binding` 字段会改变 `article_pin`，因此必须生成新的快照和审核版本，不能就地修改旧产物。

验收：每条市场路由都有 `evidence_basis`；manifest 分别记录两类路由的数量；按 `source_text` 和 `generated_summary` 分别给出面板覆盖。

#### M3：建立市场审核的人工评估集，测量准确率

问题：现有 30 条抽检中只有 3 条是人工确认，include 的精确率和 exclude 的漏判率都没有测量。

具体工作：

1. 分层抽取约 200 条记录：include、exclude 中的上游 market 候选、exclude 中的非候选、pending、`text_origin` 不同取值，各层都要有样本。区间内被排除的 191 条候选需要单独抽样，用于测量漏判。
2. 由人工按固定标注说明判定：是否属于美国股票市场整体层面的信息；事件类型；原文或摘要中能支持判断的句子。保存审核者、审核时间和标注说明版本，不得把模型复核写成人工审核。
3. 报告 include 精确率、在候选中的召回率、按 `text_origin` 分层的准确率，以及按模型自评置信度分箱的实际正确率。
4. 修改 Prompt（例如 `us_market_relevance_v3`，要求先输出事件类型再给出决定）或阈值时，只在该评估集上比较，选定后再对全库重新审核并生成新版本。依据评估集准确率决定，不依据验证集或测试集的 IC、收益来选择。

建议目录（尚未建立）：`P\news_assets\market_review_evaluation\<版本>\`，保存样本清单、人工标注、标注说明及评估结果。

验收：可以给出带样本量的 include 精确率与候选召回率；任何 Prompt 或阈值修改都附有在同一评估集上的前后对比。

#### M4：引入官方宏观事件作为结构化市场信息来源

问题：现有新闻库中与市场整体相关的文章本来就少，补审核也只能带来有限增量。宏观政策和经济数据发布是市场级信息的主要来源，它们有官方原文和精确发布时间，可以覆盖 2013～2022 年的完整区间。

建议来源（优先选择官方发布、可公开保存的内容；使用前需核实各站点的使用条款，并在上游 U 中实现，不在训练流程中联网）：

| 事件 | 来源 | 发布时间规则 |
|---|---|---|
| FOMC 声明与会议纪要 | federalreserve.gov | 声明通常在美东 14:00 发布，以官方页面时间为准 |
| CPI、非农就业 | bls.gov 新闻稿 | 通常在美东 08:30 发布 |
| GDP、个人收入与支出 | bea.gov 新闻稿 | 通常在美东 08:30 发布 |

具体工作：

1. 每条事件保存官方原文或原文摘录、来源 URL、官方发布时间、抓取时间和内容 hash，`text_origin` 记为 `source_excerpt`。
2. 只使用首次发布的文本。如果之后加入数值特征，必须使用当时首次公布的数值版本（例如 ALFRED 的 vintage 数据），不能使用后来修订过的值。
3. 发布时间早于当日行情截止时点的事件，可用于当日的预测；发布时间晚于截止时点的，顺延到下一交易日。发布时间只能以官方记录为准，不能为了覆盖而人为提前。
4. 这些事件写入独立来源 `source_type: official_macro_release`，同样经过 FinBERT 离线编码。它们属于官方文本，市场路由可以按来源类型规则生成，不需要 Qwen 审核，但必须在 manifest 中写明路由规则及其版本。
5. 实验中把“仅新闻市场路由”“仅官方宏观事件”“两者合并”作为三个独立版本，分别与 E0 比较，不只报告合并后的结果。
6. 本步骤不引入市场一致预期数据（这类数据通常需要授权）。没有一致预期就无法计算数据超预期幅度，第一版只使用事件文本本身。

验收：每个切分的官方事件数、有效日期数单独报告；所有发布时间均可追溯到官方页面；时间早于截止时点的检查通过；不同来源类型的路由在 manifest 中分开计数。

#### M5：按事件去重，报告独立事件数

问题：当前去重只比较完全相同的 `input_text_hash`，同一次 FOMC 决议的多篇改写报道会被计为多条独立信息。

具体工作：

1. 对市场路由的文章做事件聚类：发布日期相差不超过 1 个交易日，FinBERT 向量余弦相似度超过预先设定的阈值，并且事件类型相同（事件类型来自 M3 新 Prompt 的输出，或来自 M4 的官方事件类型）。
2. 为每篇文章写入 `market_event_id`。面板中 `log1p_article_count` 等统计改为按事件计数，或者同时保存文章数和事件数。
3. 覆盖报告中分别列出文章数、独立事件数和有效日期数。
4. 相似度阈值在人工抽检的样本上确定，并写入配置和 manifest。

验收：抽查的同一事件能被聚到一起，不同事件不会被错误合并；PCA 的训练样本数按独立事件报告。

#### M6：市场通道的实验就绪门槛

在运行 E3（StockMixer + 市场级新闻）之前，事先写定并在 manifest 中记录以下门槛，不根据测试结果修改：

- 训练、验证、测试三个切分都要有一定数量的独立市场事件和有效日期，具体数值在看到 M1～M5 的覆盖结果之后、首次运行 E3 之前确定。
- 单一事件类型的占比不能过高（例如超过一半时给出告警），以免市场通道实际上只代表一类事件。
- `evidence_basis: generated_summary` 的路由默认不计入正式门槛。
- 不满足门槛时，`pipeline` 阻断正式融合实验并写出原因，但仍允许运行预检查。

验收：E3 运行时的 manifest 中能查到使用的门槛、实际覆盖值和来源版本。

### 第一步：建立可解释的覆盖诊断与质量门槛

涉及现有文件：`P\news_fusion\pipeline.py`、`panel.py`、`relations.py`、`configs\llm.yaml`。

具体工作：

建议新增文件（尚未实现）：`P\scripts\12_audit_news_coverage.py`、`P\news_fusion\coverage_audit.py`。

建议产物（规划目录，尚未生成）：`P\outputs\reports\<年月日_时分秒>_NASDAQ_NYSE_SP500_coverage\`，保存 `coverage.json`、`coverage.md`、逐阶段诊断 JSONL 与分布统计。

验收：1904 条输入均能追溯；各统计口径有定义，抽样能从文章追到最终 mask；零覆盖切分会得到明确告警或正式实验阻断。

### 第二步：系统补齐公司身份与历史行业成员

涉及现有文件：`P\news_fusion\master_data.py`、`industry_mapping.py`、`scripts\07_build_historical_master.py`、`scripts\10_build_industry_mapping.py`、`configs\llm.yaml`。

具体工作：

1. 围绕三个数据集股票池，建立发行人 CIK、历史名称、代码变更、交易所、证券类别、数据集 stock_uid 与 array_index 对应。
2. 批量取得有来源的历史 SEC-SIC 观察，优先补新闻已经识别到的行业及公司，随后扩展完整股票池。
3. 分开保存“某日文档直接观察”和“该日以后使用最近已知分类”的政策结果。
4. 如采用最近已知分类沿用，配置最大陈旧期限、身份终止与变更规则；每个预测时点只使用该时点允许获知的观察。
5. 沿用结果明确标为政策推导，不能标成全区间都被原始证据直接核验；保留只使用当日观察的对照版本。
6. 新建区间政策产物，不修改旧版一天有效的证据记录，也不通过伪造起止日期制造覆盖。
7. 行业粗分类如需引入，建立有来源、有版本的 SEC-SIC 层级对应，不把多个分类标准凭名称直接合并。

建议新增文件（尚未实现）：`P\news_fusion\historical_membership_policy.py`、`P\scripts\13_build_industry_history.py`。

建议新产物：`P\outputs\artifacts\news\historical_master\<年月日_时分秒>_NASDAQ_NYSE_SP500_SEC_SIC_history\`。

验收：每条关系有身份与行业证据、证据日期、可用时间、有效范围及政策来源；针对更名、退市、换代码与行业变更进行检查；新增覆盖分别报告直接观察和政策推导的贡献。

### 第三步：补充历史新闻与审核，改善真实数据覆盖

主要操作在上游 U；下游仍通过原始快照与版本化增强结果导入。

具体工作：

1. 按第 5.3 节历史区间补采，覆盖公司公告、行业监管、行业统计、宏观政策等多种事件。
2. 保存文章正文或合法可保存的证据快照、来源链接、发布时间、首次发现、抓取时间及内容 hash。
3. 旧摘要缺正文时，能恢复原文的另存新证据版本；恢复失败保留缺失状态，不让 Qwen 编造正文。
4. 按内容去重与事件聚类，避免转载、同稿重写导致虚假的样本增长。
5. 对已有未审批市场关联进行证据审核，对公司候选做实体核验；这些工作独立于 FinBERT 编码。
6. 补采目标由时间和股票覆盖诊断决定，不根据测试集预测结果挑选新闻。

涉及现有上游文件：`U\prompts\industry_dictionary.md`、`U\offline_enrichment\industry_config.yaml`、`industry_batch.py`、`run_industry_batch.py`、`recover_industry_batch.py`。

新增强结果继续另存于 `U\data_enriched\industry_batches\<年月日_时分秒>_US_GLOBAL_<版本>\`；下游另建对应快照，不覆盖当前 v2。

验收：各切分的独立文章、有效日期、股票及行业分布显著扩展；新增实际覆盖可追溯；不以复制文章、任意延长新闻窗口或广播股票数替代数据增长。

### 第四步：提高行业候选召回与作用域识别质量

主要操作在上游 U；下游负责校验与复用，不再增加一轮常规 Qwen 行业推断。

具体工作：

1. 建立人工核验的小型评估集，覆盖公司自身事件、真正行业事件、多行业事件、无行业事件和不同地区范围。
2. 分开测量“正确行业是否进入候选”和“进入候选后是否被正确选择”，分别定位检索与 Qwen 错误。
3. 比较当前候选检索与层级检索：先选较粗行业，再从其下属标准代码中选择；保留 unknown 和空列表。
4. 每个行业关联保留逐字证据、公司级/行业级作用域、机制、方向、自评置信度、字典版本和实际推理时间。
5. 自评 0.85 不当作 85% 正确率；通过人工标注结果评估精确率、召回率与过度传播。
6. 调整提示词或候选策略后只处理受影响记录，形成新版本；旧审核不能无条件迁移。

建议上游评估目录（尚未建立）：`U\industry_data\evaluation\`，保存带审核者和审核时间的样本、判断及实际证据。不得把模型自审写成人工审核。

验收：可分别报告候选召回、行业选择、作用域判断及地区判断的质量；新策略在固定评估集上有可复核依据，不能只追求非空输出更多。

### 第五步：增加多行业差异化表示及行业中间层

这一步在覆盖改善后实施，不作为当前补齐主数据的前置条件。

建议以 `(source_id, record_version, industry_key)` 作为行业文本单元的身份，保存：

```text
industry_context_id
source_id / record_version
industry_key / dictionary_sha256
original_quote / bounded_context / source_text_sha256
scope / impact_role / direction / mechanism
evidence_type / review_status
inferred_at / feature_available_at
```

具体工作：

1. 用行业对应的原始证据及有界上下文形成编码输入，保留上下文截取位置与文本 hash。
2. 禁止把 Qwen 生成的“利好/利空”断言直接当作原始文本交给 FinBERT，以免把模型判断循环放大。
3. 为行业文本单元缓存冻结 FinBERT 概率和向量，缓存键包含文本、行业关联版本与编码模型指纹。
4. 单独保存“行业×交易日”特征，再经历史成员与暴露权重映射到“股票×交易日”。不同股票的最终修正仍由融合层学习。
5. 保留当前文章级编码作为对照。同一新闻的多行业片段仍属于同一事件，不能被统计为多个独立事件。
6. 分行业上下文编码并不自动等于可靠的行业定向情绪；如果上下文不能区分影响，需要显式保留未知并验证，不强行赋予相反情绪。

涉及现有文件：`P\news_fusion\encoder.py`、`relations.py`、`panel.py`、`configuration.py`、`configs\llm.yaml`。

建议新增文件（尚未实现）：`P\news_fusion\industry_context.py`、`P\scripts\14_encode_industry_contexts.py`。

建议产物：各新流水线目录中的 `article_industry_contexts.jsonl`、`industry_context_features\`、`<DATASET>_industry_daily\`，均带 manifest、mask 和来源关系。原三通道面板接口保留；投影维度变化时必须同步验证 `news_dim`。

验收：多行业混合新闻能展示各行业证据与不同输入；无证据不生成定向结论；映射前后能追溯且不会重复计权；PCA 只使用对应数据集训练区间拟合。

## 9. 时间和泄漏要求

- 当前实验性质为 retrospective。保留原发布时间及 2026 年实际增强、审核、编码时间，不伪称历史已在线生成。
- 若未来做 observed Point-in-Time，按真实采集、处理完成和特征可用时间执行；这些旧特征不能直接冒充历史 PIT 数据。
- 原始 `data.protocol: original` 是关闭新闻时的原代码复现选项；新闻流水线当前使用 strict。用于比较的 E0 也必须采用同一 strict 协议。
- 新闻日期、历史成员事件日期及预测日期分别处理；新闻延续数日不意味着主数据有效期自动延长。
- 只有日期的新闻保守顺延至下一交易时点；使用实际交易日轴，不做简单自然日加一。NASDAQ 市场审核记录中有 1648 / 1903 条只有日期，因此大部分新闻都会顺延一个交易日；有官方发布时间的宏观事件（M4）不受此限制，但必须使用官方记录的时间。
- 市场审核的 `known_from` 取真实审核完成时间；新补审核（M1）的时间晚于旧审核，必须如实记录，不得沿用旧审核的时间。
- PCA、标准化与选择策略仅在训练数据上拟合；验证与测试只应用固定变换。
- 历史行业沿用只能使用截止时点允许获知的观察；不能通过未来披露的行业或代码关系反向填充过去而不标记假设。
- 不能单纯加长新闻窗口、降低证据要求、复制记录、混用分类或广播全部股票来追求覆盖数字。

- 每条有效特征可追到文章、代码、股票身份、日期及证据。
- 明确区分字典提及、合格行业影响、历史成员匹配、最终预测可用四个阶段。

- 启用通道的零验证/测试覆盖得到明确限制，不能据此宣称该通道有效。
- 不改 StockMixer 主干解决数据问题；数据不足时保留 mask 与阻断原因。
- 新功能逐项验证，最终以公平 E0、消融、负对照与重复实验检验预测增益。

以上步骤有助于建立可用、可信的新闻融合实验，但不能预先保证 IC、RIC 或策略表现会提高。
